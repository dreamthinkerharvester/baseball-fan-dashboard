## Executive Summary

| 관점 | 내용 |
|------|------|
| **Problem** | KBO 팬은 경기 전 마이팀 일정·라인업·선수 컨디션을 확인하기 위해 네이버 스포츠, KBO 공식앱, 스탯티즈를 3~4탭씩 오가며 5~10분을 소비한다. 단일 화면에서 마이팀 정보를 즉시 파악할 수 있는 서비스가 존재하지 않는다. |
| **Solution** | 마구마구 카드 스타일의 라인업 시각화 + 마이팀 우선 단일 페이지 대시보드로, 팬이 30초 안에 오늘 마이팀 상황을 판독할 수 있게 한다. |
| **Function-UX Effect** | 등급별 색상 카드(엘리트=보라/레어=빨강/스페셜=노랑/노멀=파랑)가 선수 컨디션을 비언어적으로 전달하고, 카드 클릭 한 번으로 세이버 지표까지 드릴다운할 수 있어 캐주얼 팬과 통계 매니아 모두 만족시킨다. |
| **Core Value** | "경기 전 30초 판독" — 마이팀 라인업의 컨디션 등급을 카드 색상으로 즉각 파악하고 선수 기록을 한 화면에서 드릴다운. 네이버의 편의성과 스탯티즈의 데이터 깊이를 카드 UX로 결합한 유일한 팬 대시보드. |

## 1. Strategic Foundation

### 1-1. Beachhead Segment (Geoffrey Moore — Crossing the Chasm)

**선택된 비치헤드**: Persona B — 직장인 캐주얼 팬 (이수연 유형)

#### 세그먼트 비교 평가

| 기준 (1~5점) | Persona A (세이버 매니아) | Persona B (직장인 캐주얼) | Persona C (마구마구 추억충) |
|-------------|:----------------------:|:----------------------:|:------------------------:|
| **Burning Pain** | 3 (스탯티즈로 대안 있음) | **5** (마이팀 탐색 마찰 극심) | 4 (선수 맥락 부재가 아픔) |
| **Willingness to Pay** | 4 (데이터 프리미엄 감수) | 3 (무료 서비스 기대) | 2 (패션 프로젝트 기대) |
| **Winnable Market Share** | 2 (스탯티즈 충성도 높음) | **5** (네이버 불만층 이탈 중) | 4 (경쟁자 없는 노스탤지어 니치) |
| **Referral Potential** | 3 (SNS보다 커뮤니티) | **5** (카드 스크린샷 → SNS 공유) | 4 (팬카페 입소문 강함) |
| **합계** | 12 | **18** | 14 |

**선택 근거**:
- Persona B는 네이버 스포츠 UI 불만이 커뮤니티에서 가장 빈번하게 언급되는 세그먼트다 (루리웹 "경기 목록 한눈에 못 봄" 등).
- 50만 명 이상으로 추정되는 "직장인 마이팀 캐주얼 팬"은 현재 대안이 없다. 6~18개월 내 60% 점유가 가능한 실질적 공백이다.
- 카드 스크린샷 SNS 공유 행동이 자연 발생적 바이럴 루프를 만든다. 이 세그먼트는 추천 잠재력이 가장 높다.
- 마케팅 비용 없이 야갤·팀 카페 커뮤니티 seeding만으로 초기 진입 가능하다.

#### 90일 고객 확보 계획

| 기간 | 활동 | 목표 |
|------|------|------|
| 1~2주 (Phase 0) | 크롤러 POC + 목업 hallway test 5~8명 (지인 팬 대상) | 가설 검증, 제품 방향 확정 |
| 3~4주 | MVP 개발. 야갤·LG/KIA/삼성 팬카페에 스크린샷 + URL seeding | DAU 200~500 달성 |
| 5~8주 | 피드백 반영 빠른 패치. 트위터/X 야구팬 계정 공유 | DAU 1,000 달성 |
| 9~12주 | 마이팀 카드 이미지 공유 기능 추가. 인플루언서 야구 유튜버 제보 | DAU 3,000~5,000 달성 |

### 1-2. GTM Strategy

#### 채널 평가

|------|------|:------:|:----:|:------------:|

| 팀별 팬카페 (LG·KIA·삼성 등) | 커뮤니티 seeding | ★★★★☆ | 0 | 1순위 |
| 트위터/X 야구팬 계정 | 소셜 공유 | ★★★★☆ | 0 | 2순위 |
| 인스타그램 카드 이미지 공유 | 바이럴 콘텐츠 | ★★★☆☆ | 0 | 2순위 |
| 야구 유튜버 제보 | 인플루언서 | ★★★☆☆ | 0 | 3순위 |
| 엠엘비파크 KBO타운 | 커뮤니티 seeding | ★★★☆☆ | 0 | 3순위 |
| Google SEO | 콘텐츠 | ★★☆☆☆ | 0 | 중장기 |

#### 핵심 메시지 (채널별)

- **야갤/팬카페**: "네이버 스포츠 대신 써보세요. 마이팀 선발 라인업 등급 색상으로 30초 판독."
- **트위터/X**: "오늘 [팀명] 라인업 보셨어요? 엘리트 2명 레어 1명 [이미지]"
- **인스타그램**: 카드 스크린샷 이미지 중심. 텍스트 최소화.

#### Launch Sequence

```
[Pre-Launch — Phase 0, 1~2주]
  └── 목업 hallway test → 크롤러 POC 완료 → 소수 지인 베타 링크 공유

[Launch Day — MVP 배포일]
  └── 야갤 + LG/KIA 팬카페 동시 스레드 게시
  └── 트위터 "마이팀 라인업 카드" 스크린샷 3장 공유
  └── GitHub README 공개 (투명성 신뢰 구축)

[Post-Launch — 2~4주]
  └── 피드백 빠른 반영 (24~48시간 핫픽스 사이클)
  └── DAU 데이터 모니터링 → 커뮤니티 언급 추적
  └── 엠엘비파크·트위터 야구 계정 추가 seeding
```

#### 90일 GTM 로드맵

| 주차 | 마일스톤 | 성공 지표 |
|------|---------|----------|
| 1~2주 | POC + hallway test 완료 | hallway test 70% "편하다" 평가 |
| 3~4주 | MVP 배포 + 커뮤니티 seeding | DAU 500, 커뮤니티 언급 5건 이상 |

| 9~12주 | 카드 공유 기능 추가 + 유튜버 제보 | DAU 5,000, 공유 카드 이미지 100건/주 |

### 1-4. Competitive Battlecard

#### vs. 네이버 스포츠

| 항목 | 우리 (KBO 카드 대시보드) | 네이버 스포츠 야구 |
|------|----------------------|-----------------|
| **포지셔닝** | 마이팀 우선 단일화면 + 카드 UX 전문 팬 도구 | 범용 스포츠 포털의 야구 섹션 |
| **핵심 강점** | 마이팀이 기본 화면 / 카드 색상 등급 / WAR·OPS 포함 세이버 지표 / 광고 없음 | 압도적 MAU, 마이팀 알림, 커뮤니티(오픈톡), 기사·영상 통합 |
| **핵심 약점** | 신생 프로젝트, 낮은 인지도, 크롤링 의존 데이터 | 세이버 지표 없음, 마이팀 설정 4단계 복잡, KBO 생중계 없음, 정보 과부하 |
| **가격** | 완전 무료 (후원 선택) | 무료 (프리미엄 없음) |
| **최적 대상** | 세이버 지표 + 카드 감성 원하는 코어~캐주얼 팬 | 기사·하이라이트·중계 원하는 일반 팬 |

**Win 전략**: "네이버는 기사 보는 곳, 이건 라인업 보는 곳"으로 역할 분리. 설정 복잡도 vs. 원클릭 온보딩을 핵심 대비점으로 강조.

**자주 나오는 objection과 응답**:
- *"네이버가 더 많은 정보 주잖아요"* → "네이버는 기사·댓글까지 다 줘서 내 팀 라인업 찾는 데 3탭 걸립니다. 여기선 들어오면 바로 마이팀 카드가 뜹니다."
- *"네이버 신뢰도가 더 높지 않나요"* → "경기 일정·순위·라인업 데이터 소스는 동일하게 KBO 공식 사이트입니다. 다른 건 화면 구조입니다."

#### vs. 스탯티즈 (STATIZ)

| 항목 | 우리 (KBO 카드 대시보드) | 스탯티즈 |
|------|----------------------|---------|
| **포지셔닝** | 세이버 데이터를 카드 UX로 래핑한 모바일 친화 대시보드 | 야구 분석가·기자가 쓰는 KBO 세이버 데이터 표준 |
| **핵심 강점** | 모바일 최적화, 카드 시각화, 등급 색상, 온보딩 30초 | WAR·wRC+·FIP·투구궤적 등 최고 수준 지표 깊이, 커뮤니티 신뢰도 |
| **핵심 약점** | 스탯티즈 수준의 지표 완성도 미달 (MVP 기준) | 모바일 반응형 없음, 시각화 전무, 진입장벽 높음, "이 숫자가 좋은 건지 나쁜지" 맥락 없음 |
| **가격** | 완전 무료 | 무료 (STATIZ PLUS는 유료) |
| **최적 대상** | 세이버 입문자 + 카드 감성 원하는 팬 | 야구 분석 전문가·기자·세이버 헤비유저 |

**Win 전략**: "스탯티즈는 엑셀, 우리는 게임 UI"로 포지셔닝. 스탯 자체보다 "이 선수 오늘 핫해? 콜드해?" 맥락 전달이 차별화 포인트.

**자주 나오는 objection과 응답**:
- *"스탯티즈가 훨씬 정확하잖아요"* → "스탯티즈 데이터를 참조해서 카드 등급을 산출합니다. 데이터는 같고 경험이 다릅니다."
- *"WAR이 없으면 의미 없어요"* → "MVP에서는 wRC+·OPS·ERA·FIP을 제공합니다. WAR은 Phase 2에서 추가할 예정입니다."

## 2. Product Vision & Goals

### Vision

"KBO 팬이 경기 전 30초 안에 마이팀 라인업 컨디션을 마구마구 카드 색상으로 판독하고, 한 화면에서 일정·순위·선수 기록까지 드릴다운할 수 있는 최고의 팬 대시보드."

### Goals

| 기간 | 목표 |
|------|------|
| **MVP 목표** (4주) | 크롤링 안정성 95% 이상 달성. 10팀 일정·순위·마이팀 라인업 카드 9장 동작 확인. hallway test 70% 이상 "편하다" 평가. |
| **3개월 목표** | DAU 3,000 달성. 세션당 카드 클릭 2회 이상. 마이팀 선택 전환율 60% 이상. 커뮤니티 자연 언급 50건 이상. |
| **1년 목표** | DAU 10,000 달성. 시즌 중 주간 방문자 7만 이상. 카드 이미지 공유 기능 통해 주 500건 이상 소셜 공유 발생. SOM 1.5억 원/년 달성 (광고 기반). |

### North Star Metric

**"마이팀 설정 유저의 일일 대시보드 방문 완료율"** (DAU 중 마이팀 설정 완료 후 재방문하는 비율)

- 목표: 경기일 기준 60% 이상이 당일 재방문

### 지원 지표 (3개)

| 지표 | 정의 | MVP 목표 | 3개월 목표 |
|------|------|:--------:|:---------:|
| **카드 클릭율** | 세션당 선수 카드 클릭 수 (참여도) | 1.0회/세션 | 2.0회/세션 |
| **마이팀 전환율** | 방문자 중 마이팀 설정 완료 비율 | 40% | 60% |
| **커뮤니티 언급** | 야갤·팬카페에서 자연 발생 언급 수/주 | 5건 | 50건 |

## 4. Functional Requirements (MVP — Phase 1)

### F1. 팀 일정 뷰 (10팀)

**목적**: O1 기회 해결. 오늘 + 이번 주 전체 10팀 경기 일정을 단일 뷰에서 제공.

**데이터 필드**:
- 홈팀명, 원정팀명, 경기 시작 시간 (HH:MM), 경기장명 (구장 약칭)
- 경기 상태: 예정 / 진행 중 / 완료 / 취소(우천 등)
- 경기 완료 시: 최종 스코어 (홈팀 점수 - 원정팀 점수)

**인터랙션**:
- 기본 뷰: 오늘 경기 목록 (타임라인 형태, 시간순 정렬)
- 탭 전환: 오늘 / 이번 주 / 이번 달
- 마이팀 경기 하이라이트 (배경 또는 보더 강조)

**엣지 케이스**:
- 더블헤더: 같은 팀 2경기 모두 표시 (DH1, DH2 구분 레이블)
- 우천 취소: "취소" 배지, 회색 처리
- 오늘 경기 없는 팀: 팀 목록에서 표시하되 "경기 없음" 처리 (숨기지 않음)
- 자정 넘어가는 경기 (연장): 해당일 경기로 처리

**데이터 갱신**: 매 10분 크롤링 캐시 갱신 (경기 중에는 5분)

---

### F2. 마이팀 선택 + localStorage 저장

**목적**: O7 기회 해결. 로그인 없이 팀 개인화 즉시 제공.

**기능 명세**:
- 첫 방문 시: 10팀 로고(또는 팀명 버튼) 선택 화면 → 클릭 1회로 설정 완료
- localStorage key: `baseball_myteam`, value: 팀 코드 (예: `"LG"`)
- 마이팀 변경: 설정 아이콘 → 팀 재선택 (현재 팀 하이라이트 상태로 재진입)
- 설정 삭제: "마이팀 초기화" 옵션 → localStorage 항목 삭제 → 첫 방문 화면으로 복귀

**인터랙션 흐름**:
```
URL 접속
  └── localStorage에 myteam 있음? → 마이팀 대시보드 바로 표시
  └── 없음? → 팀 선택 화면 → 선택 → 대시보드 즉시 전환 (페이지 리로드 없음)
```

**엣지 케이스**:
- localStorage 비활성화 환경(시크릿 모드 등): 세션 유지, 탭 닫으면 초기화. 안내 배너 표시.
- 브라우저 다름: 디바이스·브라우저가 달라지면 재설정 필요. 로그인 기능(Phase 2)으로 해결 예정.

---

### F3. 마이팀 라인업 카드 (마구마구 스타일, 9~10장)

**목적**: O2 기회 해결. 타순별 선수 카드 9장 (DH 포함 시 10장).

**카드 1장 기본 구성 (레이아웃)**:
```
┌─────────────────────────┐
│  [등급 배지]  [타순 번호] │  ← 상단 헤더
│                         │
│    [선수 사진/아바타]    │  ← 중앙 (사진 없을 경우 포지션 아이콘)
│                         │
│   선수명 (한글)          │  ← 이름
│   포지션 · 팀 로고       │  ← 서브 정보
│                         │
│   대표 스탯 1개          │  ← 타자: OPS 또는 타율 / 투수: ERA
│   (시즌 누적 기준)       │
└─────────────────────────┘
```

**카드 색상 테마 (등급별)**:
- 엘리트 (상위 10%): 보라색 보더 + 보라 글로우 이펙트 `#7B2FBE` / glow `rgba(123,47,190,0.4)`
- 레어 (11~30%): 빨간색 보더 + 빨강 글로우 `#E63946` / glow `rgba(230,57,70,0.4)`
- 스페셜 (31~60%): 노란색 보더 + 노랑 글로우 `#F4A261` / glow `rgba(244,162,97,0.4)`
- 노멀 (61~100%): 파란색 보더 (글로우 없음) `#457B9D`

**카드 그리드 레이아웃**:
- 모바일: 3열 × 3행 + 투수 1장 (별도 섹션)
- 데스크탑: 5열 × 2행 배치 가능

**라인업 미확정 상태**: 카드 그리드 자리 유지, 흐린 플레이스홀더 표시 + "라인업 공개 전" 오버레이

**데이터 갱신**: 경기 당일 오전 10시부터 30분마다 갱신. 라인업 확정 후 고정 (갱신 주기 1시간으로 전환).

### F4. 카드 클릭 → 선수 상세 모달

**목적**: O3 기회 해결. 카드 감성을 유지하면서 깊이 있는 지표 접근.

**모달 구성**:
```
┌─────────────────────────────────────────┐
│ [선수명]  [팀]  [포지션]  [등급 배지]  [X] │
├─────────────────────────────────────────┤
│ [시즌 성적 탭] | [역대 기록 탭]          │
├─────────────────────────────────────────┤
│ 시즌 성적 탭:                            │
│   타자: 타율 / OPS / wRC+ / HR / RBI    │
│   투수: ERA / FIP / WHIP / K/9 / BB/9  │
│                                         │
│ 최근 10경기 트렌드 (미니 스파크라인)      │
│ ████░░░░░░  (OPS 기준 경기별 막대)       │
├─────────────────────────────────────────┤
│ 역대 기록 탭:                            │
│   연도별 시즌 성적 테이블                 │
│   (최근 5시즌 기본, 전체 토글 가능)       │
└─────────────────────────────────────────┘
```

**인터랙션**:
- 카드 클릭/탭 → 모달 슬라이드업 애니메이션 (300ms)
- 배경 클릭 또는 X 버튼 → 모달 닫기, 대시보드 복귀 (스크롤 위치 유지)
- 스와이프 다운 (모바일) → 모달 닫기

**엣지 케이스**:
- 신인 선수 (역대 기록 1년): "역대 기록" 탭에 "첫 시즌 진행 중" 안내
- 최근 10경기 데이터 부족 (부상 복귀 등): 가용 데이터 기준으로 표시, "n경기 기준" 레이블 추가
- 외국인 선수: 국내 시즌 기록만 표시 (해외 기록은 미지원, Phase 2)

### F5. 단일 페이지 정보 밀집 레이아웃

**목적**: O4 기회 해결 + 정보 집약 UX 가설 (A3) 검증.

**페이지 구조 (위에서 아래)**:
```
[상단 고정 헤더]
  → 앱 타이틀 · 마이팀 변경 버튼 · 날짜

[섹션 1: 리그 순위 배너]
  → 10팀 축약 순위표 (팀명, 승률, 게임차)
  → 마이팀 하이라이트

[섹션 2: 오늘 경기 일정]
  → 전체 경기 타임라인 또는 마이팀 경기 강조 뷰

[섹션 3: 마이팀 라인업 카드]
  → 오늘 선발 라인업 9장 카드 그리드
  → (라인업 미확정 시 플레이스홀더)

[섹션 4: 선수 상세 모달]
  → 카드 클릭 시 오버레이
```

**UX 원칙**:
- 스크롤 없이 핵심 3요소(순위·일정·라인업)가 한 화면에 들어오도록 정보 밀도 최적화 (모바일 기준 375px × 812px 내 배치 목표)
- 순위 배너는 접힘/펼침 토글 가능 (공간 절약 모드)
- 마이팀 라인업 섹션은 항상 화면 중심 위치 고정

| 소스 | 용도 | 신뢰도 | 리스크 |
|------|------|:------:|:------:|
| KBO 공식 사이트 (koreabaseball.com) | 일정·순위·공식 라인업 | 높음 | robots.txt 차단, 구조 변경 |
| 스탯티즈 (statiz.co.kr) | 세이버 지표 (wRC+·FIP·OPS) | 높음 | rate-limit, 접근 차단 |
| 구단 공식 SNS (보조) | 라인업 확정 타이밍 감지 | 중간 | API 없음, 비정형 |

**원칙**: 두 소스(KBO + 스탯티즈) 병렬 크롤링. 한 소스 실패 시 다른 소스 데이터로 서빙. 캐시 레이어로 실시간 크롤링 의존 최소화.

### 크롤러 아키텍처

```

  ├── 매일 오전 7시: 경기 일정 크롤링 (KBO)

  ├── 크롤링 실패: 마지막 성공 캐시 데이터 서빙 + "데이터 갱신 지연" 배너

```

### 추천 기술 스택

| 레이어 | 선택 | 이유 |
|--------|------|------|
| **프레임워크** | Next.js 14+ (App Router) | SSR로 SEO 기반 구축, API Routes로 크롤링 캐시 서빙, Vercel 최적화 |

| **스케줄러** | GitHub Actions (cron) | 완전 무료, 코드와 함께 버전 관리, Discord 알림 연동 용이 |
| **호스팅** | Vercel (무료 티어) | Next.js 최적화, Edge Cache, 배포 자동화 |
| **분석** | Umami (셀프 호스팅) 또는 GA4 | 프라이버시 친화, 무료 |

### 인증 없는 MVP 결정

MVP에서 로그인을 도입하지 않는 근거:
1. 마이팀 설정은 localStorage로 충분 (단일 디바이스 사용 패턴).
2. 로그인 온보딩은 이탈 마찰을 증가시킨다. Persona B는 30초 온보딩이 핵심.
3. 사용자 데이터를 서버에 저장할 법적 의무(개인정보보호법)가 생기는 것을 Phase 2로 미룬다.
4. Phase 2에서 "선호 선수 즐겨찾기 + 알림"이 추가될 때 소셜 로그인(카카오) 도입 예정.

## 9. Card Grade System Spec (등급 산출 알고리즘)

### 등급 정의 및 색상

| 등급 | 백분위 기준 | 카드 색상 | 보더 컬러 | 글로우 컬러 | 배지 텍스트 |
|------|:----------:|---------|:--------:|:----------:|:----------:|
| **엘리트** | 상위 0~10% | 보라 | `#7B2FBE` | `rgba(123,47,190,0.5)` | ELITE |
| **레어** | 상위 11~30% | 빨강 | `#E63946` | `rgba(230,57,70,0.4)` | RARE |
| **스페셜** | 상위 31~60% | 노랑/주황 | `#F4A261` | `rgba(244,162,97,0.4)` | SPECIAL |
| **노멀** | 61~100% | 파랑 | `#457B9D` | 없음 | NORMAL |

### 타자 등급 산출

**1단계: 지표 선택**
- 주 지표: **wRC+** (가중 득점 창출 지수, 리그 평균 = 100)
- wRC+ 데이터 없을 경우 대체: OPS

**2단계: 최근 10경기 이동 평균 계산**
```
recent_ops_10g = SUM(last_10_games.ops_per_game) / n_games
recent_wrcp_10g = 스탯티즈 API에서 최근 10경기 wRC+ 직접 수집
```

**3단계: 리그 전체 백분위 계산**
```
# 현재 시즌 규정 타석 기준 타자 집단 내 백분위
percentile_rank = (선수보다 낮은 wRC+_10g 타자 수 / 전체 비교 대상 타자 수) × 100
```

**4단계: 등급 매핑**
```
if percentile_rank >= 90: grade = "elite"
elif percentile_rank >= 70: grade = "rare"
elif percentile_rank >= 40: grade = "special"
else: grade = "normal"
```

**데이터 부족 예외 처리**:
- 최근 10경기 중 5경기 미만 기록 (부상 복귀 등): 가용 경기 데이터 사용 + "n경기 기준" 레이블
- 신인 시즌 초반 (5경기 미만): 시즌 누적 스탯으로 대체
- 투수가 타자 포지션 배치 (DH 등): 투수 기준 등급 유지

### 투수 등급 산출

**1단계: 지표 선택**
- 주 지표: **FIP** (수비 독립 평균 자책점, 낮을수록 좋음)
- FIP 데이터 없을 경우 대체: ERA

**2단계: 최근 10경기 (선발: 10선발 / 불펜: 10등판) 이동 평균**
```
recent_fip_10g = 최근 10등판의 평균 FIP
```

**3단계: 백분위 계산 (FIP는 낮을수록 좋으므로 역순)**
```
# 규정 이닝 기준 투수 집단 내 백분위 (낮은 FIP = 높은 백분위)
percentile_rank = (선수보다 높은 FIP_10g 투수 수 / 전체 비교 대상 투수 수) × 100
```

**4단계: 등급 매핑 (타자와 동일)**
```
if percentile_rank >= 90: grade = "elite"
elif percentile_rank >= 70: grade = "rare"
elif percentile_rank >= 40: grade = "special"
else: grade = "normal"
```

### 등급 갱신 주기

- 매일 오전 6시: 전날 경기 반영 후 전체 선수 등급 일괄 재산출
- 시즌 초 (1~2주, 경기 수 10 미만): 등급 시스템 비활성화, "시즌 초 — 등급 집계 중" 표시
- 비시즌: 마지막 시즌 최종 등급 유지 (static display)

**목적**: 가장 위험한 가정(A1, A4, A3)을 코드 한 줄 없이 검증.

**범위**:
- [ ] KBO 공식 사이트 크롤러 POC: 일정·순위·라인업 3종 데이터 7일 연속 수집 (성공률 목표 95%+)
- [ ] 스탯티즈 크롤러 POC: 타자 wRC+·OPS, 투수 ERA·FIP 수집 안정성 확인
- [ ] 라인업 공개 타이밍 수동 모니터링 2주: 80% 이상 경기에서 시작 2시간 전 라인업 확보 여부
- [ ] 정보 집약형 단일 페이지 목업 vs. 탭 분리형 목업 hallway test 5~8명 (지인 야구팬)

**성공 기준 (Exit Gate)**:
- 크롤러 성공률 95% 이상 달성
- 라인업 타이밍 80% 이상 검증
- hallway test 70% 이상 "단일 페이지 더 편하다" 평가

**실패 시 대안**:
- 크롤러 실패: KBO 모바일 앱 네트워크 트래픽 역공학 → 비공식 JSON 엔드포인트 활용
- 타이밍 실패: "라인업 미확정" 플레이스홀더를 기본 UX로 설계
- hallway test 실패: 탭 분리형 구조로 전환 검토

### Test Scenarios

#### TS-01: Happy Path — 첫 방문 온보딩 (US-01)

| 항목 | 내용 |
|------|------|
| **전제 조건** | 신규 사용자, localStorage 비어있음, 오늘 경기 있는 날 |
| **테스트 절차** | 1. URL 접속 → 팀 선택 화면 표시 확인 (2초 이내) → 2. "LG" 선택 1회 클릭 → 3. 마이팀 대시보드 즉시 표시 → 4. localStorage `baseball_myteam = "LG"` 확인 → 5. 페이지 새로고침 → 6. LG 대시보드 바로 표시 확인 |
| **예상 결과** | 6단계 모두 정상 통과. 팀 선택 → 대시보드 전환 1초 이내. 새로고침 후 팀 유지. |
| **Priority** | P0 |

#### TS-02: Happy Path — 라인업 카드 등급 색상 (US-03, US-04)

| 항목 | 내용 |
|------|------|
| **전제 조건** | 마이팀 설정 완료, 오늘 경기 라인업 공개 상태, 선수 최근 10경기 데이터 존재 |
| **테스트 절차** | 1. 마이팀 라인업 섹션 진입 → 2. 9장 카드 그리드 표시 확인 → 3. 각 카드 등급 배지(ELITE/RARE/SPECIAL/NORMAL) 표시 확인 → 4. 등급별 보더 색상 일치 확인 (엘리트=보라, 레어=빨강, 스페셜=노랑, 노멀=파랑) → 5. 엘리트 카드 글로우 이펙트 표시 확인 |
| **예상 결과** | 9장 카드 모두 등급 배지 + 색상 올바름. wRC+ 상위 10% 선수 = 보라 카드. |
| **Priority** | P0 |

#### TS-03: Edge Case — 라인업 미확정 상태 (US-09)

| 항목 | 내용 |
|------|------|
| **전제 조건** | 마이팀 설정 완료, 오늘 경기 있음, 라인업 미공개 상태 |
| **테스트 절차** | 1. 마이팀 라인업 섹션 진입 → 2. 플레이스홀더 카드 9장 표시 확인 → 3. "라인업 미확정 — 경기 시작 2시간 전 공개 예정" 텍스트 표시 확인 → 4. 새로고침 버튼 클릭 → 5. 크롤러 재조회 후 상태 갱신 확인 |
| **예상 결과** | 빈 데이터 에러 없이 플레이스홀더 UI 표시. 새로고침 버튼 동작. 라인업 확정 후 실제 카드로 자동 전환. |
| **Priority** | P0 |

#### TS-04: Edge Case — 크롤링 실패 (데이터 없음)

| 항목 | 내용 |
|------|------|
| **전제 조건** | 크롤링 소스 일시 장애. 캐시 데이터 있음. |
| **테스트 절차** | 1. 크롤러 응답 없음 시뮬레이션 (환경 변수로 모킹) → 2. 대시보드 접속 → 3. 캐시 데이터 표시 확인 → 4. "데이터 갱신 지연 — 마지막 업데이트: HH:MM" 배너 표시 확인 → 5. Discord 웹훅 알림 발송 확인 |
| **예상 결과** | 서비스 중단 없이 캐시 데이터 서빙. 사용자에게 갱신 지연 안내. 개발자 알림 발송. |

| 항목 | 내용 |
|------|------|

| **테스트 절차** | 1. `localStorage.setItem('baseball_myteam', 'INVALIDTEAM')` 실행 → 2. 대시보드 접속 → 3. 잘못된 팀 코드 처리 확인 → 4. 팀 선택 화면으로 폴백 확인 또는 기본 팀(KBO 전체 뷰)으로 폴백 확인 |
